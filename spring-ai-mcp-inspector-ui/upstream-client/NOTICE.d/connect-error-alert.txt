src/lib/connectErrors.ts + src/lib/hooks/useConnection.ts +
 src/components/Sidebar.tsx + src/App.tsx — surface connect failures
 with a reason and a Retry button. When the Java proxy answers
 POST /mcp-inspector-api/mcp with the structured non-2xx contract
 `{"error":{"code":"MCP_CONNECT_FAILED","reason":"<timeout|connection_refused|dns|unknown>","message":"...","retryable":true}}`,
 the SDK transport would only see an opaque HTTP-status error and the
 sidebar silently stayed "Disconnected". Local fix: the proxy
 streamable-http transport gets a fetch wrapper that parses the
 contract out of non-ok responses and throws `ConnectFailedError`
 (non-contract bodies pass through untouched); the connect() catch
 stores the failure instead of throwing into an unhandled rejection;
 the sidebar renders it as a `role=alert` with a human-readable
 reason and a Retry button that repeats connect. Covered by
 src/lib/__tests__/connectErrors.test.ts and
 src/components/__tests__/Sidebar.connectFailureAlert.test.tsx.

Additional fix on top of the connect-failure alert:
- Sidebar.tsx status text depends on connectionError?.reason instead
  of unconditionally mentioning the proxy token: connection_refused
  and dns show "URL is reachable", timeout shows "not responding",
  unknown/fallback shows "MCP server is running".
