src/utils/paramValidation.ts (new) + src/components/ToolsTab.tsx +
 src/components/PromptsTab.tsx: client-side required/type validation
 for tool-call parameters and prompt arguments, with derived disabled
 state on the Run Tool and Get Prompt buttons.

What changed for the user:
- The Run Tool button is now disabled immediately when a tool with
  required fields is selected, without requiring the user to blur
  every field first. Validation is computed on every render from the
  tool's inputSchema plus current params (derived), not from a flag
  set by a blur event.
- Required primitive fields (string/number/enum) without a
  schema.default stay absent from state and are omitted from the
  submit payload, so a `sum` tool no longer silently sends
  `{a:0,b:0}` when the user never typed anything. Required boolean
  and object/array fields without a default seed the value their
  widget already displays (false / generated default such as {})
  into state, so Run Tool is not stuck disabled with no hint and the
  payload agrees with what the form shows.
- Numeric inputs parse strictly: only plain decimal and scientific
  notation become numbers. Whitespace, hex ("0x1F") and "Infinity"
  stay strings for the server to reject instead of silently becoming
  0/31/null.
- The Get Prompt button follows the same rules: disabled when a
  prompt with required arguments is untouched.

Implementation:
- `src/utils/paramValidation.ts` (new): pure functions
  `validateToolParams(schema, params)` and
  `validatePromptArgs(args, promptArgs)` returning per-field errors.
  Rules: required array checked; undefined/null/empty-string is
  "required"; integer must be a whole number; number must be a
  number; boolean must be a boolean; `nullable: true` accepts null;
  ambiguous schemas (no clear primitive type) are skipped. The
  server round-trip handles them.
- `src/components/ToolsTab.tsx`: fieldErrors state kept for blur/
  submit hint display only; the button's disabled state derives from
  `validateToolParams(schema, params)` on every render, combined
  with the existing hasValidationErrors (DynamicJsonForm) check.
  The initialization effect seeds fields that declare a `default` in
  the schema, plus required boolean fields (false) and required
  object/array fields (generateDefaultValue()) without a default;
  other required primitives stay absent from the initial params
  object. Numeric onChange parses strictly (decimal/scientific
  regex). DynamicJsonForm onChange handlers use functional setParams
  plus a paramsRef to avoid stale closures. formRefs.current is reset
  in the effect when switching tools (upstream behavior restored).
- `src/components/PromptsTab.tsx`: same pattern. validatePromptArgs
  drives the disabled state on Get Prompt; fieldErrors only shown
  after touch.

`src/components/ui/combobox.tsx`: added optional aria-invalid and
  aria-describedby props, forwarded to trigger Button.
`src/components/ToolsTab.tsx`: error paragraphs get stable id and
  role="alert"; all controls (textarea, numeric input, enum select,
  boolean checkbox, DynamicJsonForm wrappers) get aria-invalid and
  aria-describedby pointing to their error paragraph.
`src/components/PromptsTab.tsx`: same pattern for the combobox
  trigger and its error paragraph.

Covered by:
- `src/utils/__tests__/paramValidation.test.ts`: unit tests for
  both validation functions (required, type checks, nullable, union
  types, ambiguous schemas).
- `src/components/__tests__/ToolsTab.test.tsx`: untouched sum tool
  → Run Tool disabled; submit payload regression test (a=2,b=3
  sends exactly {a:2,b:3}); aria-invalid and aria-describedby
  verified after blur of empty required textarea; hint-lifecycle
  regression tests (issue #256): a blur hint on a required textarea
  or numeric input clears on the next change without another blur,
  and an empty required enum select carries aria-invalid,
  aria-describedby and border-red-500 on its trigger after close.
  Seeded shown values and strict numeric parse: a required boolean
  submits false without touching the form, a required object submits
  its generated default, and whitespace/hex/Infinity never become
  numbers while 1.5e2 parses to 150.
- `src/components/__tests__/PromptsTab.test.tsx`: untouched prompt
  → Get Prompt disabled; fills required arg → button enabled;
  aria-invalid and aria-describedby verified on combobox trigger
  after blur.
