 src/components/__tests__/Sidebar.connectFailureAlert.test.tsx :
show structured timeout detail in the connect error banner.

The proxy reports per-phase connection timeouts on the existing
MCP_CONNECT_FAILED contract with reason "timeout" plus phase/elapsedMs/
budgetMs numbers (ProxyConnectionBudgets.timeoutBody on the server;
byte-for-byte fixture in ProxyConnectionBudgetsTests). The parser reads
those fields on that branch, so the sidebar banner shows which phase
timed out (Transport connect / MCP initialize) and the elapsed/budget
numbers as "X.Xs of Ys".

A separate connection_timeout code is still accepted by the parser as
future-proofing, but the server never sends it (the
ProxyConnectionBudgets javadoc says "No separate error code", and
ProxyConnectionBudgetsTests asserts the absence of the key). No test
treats that alias as the only proof of the banner working.

The clickable "Increase Connection timeout" hint is intentionally
absent: the connection-timeout input ships in PR #241, so until it
lands there is no field to focus and the hint would be a silent no-op
(review finding F3 on #243).

Non-structured errors (no phase field) fall through to the existing
generic timeout banner unchanged.

Covered by:
- connectErrors.test.ts: parsing the proxy timeout payload (the real
  MCP_CONNECT_FAILED wire shape from ProxyConnectionBudgetsTests), the
  connection_timeout alias, humanReadablePhase(),
  formatBudgetBreakdown()
- Sidebar.connectFailureAlert.test.tsx: structured timeout banner
  render, budget display, end-to-end parse of the real payload into
  the banner, fallback for unstructured errors
