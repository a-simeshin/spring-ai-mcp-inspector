src/App.tsx, src/lib/hooks/useConnection.ts, src/components/TasksTab.tsx -- gate
all tasks/* RPC calls on the advertised server capabilities (issue #212, PR #214).

Changes:
1. App.tsx: added serverCapabilitiesRef (useRef synced with serverCapabilities
   state) so the notification callback installed before connect completes reads
   the current capabilities, not the stale null closure. The notification handler
   now checks serverCapabilitiesRef.current?.tasks before calling listTasks().
2. App.tsx: polling loop (tools/call runAsTask path) checks
   serverCapabilitiesRef.current?.tasks before each iteration and aborts
   gracefully when the server no longer advertises tasks (disconnect/reconnect).
3. App.tsx: listTasks callback is gated on
   serverCapabilitiesRef.current?.tasks?.list (operation-level sub-capability).
4. App.tsx: cancelTask is gated on
   serverCapabilitiesRef.current?.tasks?.cancel (operation-level sub-capability).
5. App.tsx: the activeTab effect for tasks/list is gated on
   serverCapabilities?.tasks?.list (not just tasks truthiness).
6. useConnection.ts: added serverCapabilitiesRef (same pattern as App.tsx).
   listTasks and cancelTask now early-return when the respective operation
   sub-capability is absent, preventing stale -32601 errors after
   disconnect/reconnect to a capability-less server.
7. TasksTab.tsx: empty state with the exact message from issue #212:
   "Server does not advertise the tasks capability; long-running task tracking
   is unavailable." The primary affordance for the absent capability is the
   disabled tab trigger with tooltip (existing tasks-tab-tooltip.txt patch);
   this empty state is the fallback for programmatic navigation.

Covered by:
- src/__tests__/App.tasksCapabilityGating.test.tsx (App-level integration)
- src/lib/hooks/__tests__/useConnection.test.tsx (hook-level unit tests)
